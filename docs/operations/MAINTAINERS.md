# 维护者与维护边界

CodeRook 当前是单维护者项目。仓库所有者 `@kyletser` 是当前唯一发布者与最终合并者；这是一项
总线因子风险，不把 `CODEOWNERS` 的自审误写成多人安全复核。

## 责任边界

| 领域 | 维护责任 | 合并所需证据 |
|---|---|---|
| Agent loop、工具、TUI | 行为正确、失败可恢复、用户状态可理解 | 窄测试；用户面变更附截图或事件证据 |
| 权限、sandbox、凭据 | fail-closed、诚实降级、秘密不落日志 | 负例与威胁模型更新 |
| IPC、HTTP/SSE、SDK | 兼容窗口、生成协议与迁移说明 | 协议检查、兼容测试与 Changelog |
| runtime、ledger、workflow | 崩溃一致性、幂等恢复、可审计 | 中断/恢复测试与数据迁移说明 |
| benchmark、release | 固定配置、不可变产物、公开可复现 | 报告、checksums、SBOM、attestation |
| 文档与示例 | 命令可运行、不夸大状态、无个人数据 | 链接检查与最短路径 smoke |

贡献者可以提出、实现和评审任何公开改动，但以下操作只由维护者执行：安全漏洞协调、仓库权限与
ruleset 修改、Secret 配置、tag、正式发布和安全公告。外部贡献不需要向维护者提供模型 API key。

## 评审与晋升

项目不承诺响应 SLA。维护者按安全影响、用户阻塞程度和可复现性分诊；无法复现、越过任务边界或
没有验证证据的 PR 可能延后。持续贡献者在具备以下证据后可获得组件维护权限：多次小而完整的 PR、
能识别该组件安全/兼容边界、能评审他人改动、且连续维护一段时间。发布与仓库管理权限最后授予。

新增第二位活跃维护者后，应更新 `CODEOWNERS` 为真实组件所有权、把 main ruleset 的批准数改为 1，
并要求高风险路径的 code owner review。维护者退出时先撤销外部权限和发布凭据，再更新本文件与
`.github/GOVERNANCE.md`；无人维护时应明确归档，而不是继续接受无法处理的安全报告。
